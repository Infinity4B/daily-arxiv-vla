Evaluating Multimodal LLMs as Generalist Vision-Language-Action Agents for Drone Control: Commanding, Approaching, Tracking and Searching

2026-09-01 · 原文 · 翻译 · 2609.01404

论文研究多模态大语言模型（MLLM）作为通用视觉-语言-动作（VLA）智能体直接控制无人机的闭环能力，涵盖指挥（Commanding）、接近（Approaching）、跟踪（Tracking）和搜索（Searching）四类任务。 现有系统（如 TypeFly、PIVOT、SPF、Fly0、OnFly）通过外部检测器、候选点选择、LiDAR 规划器或验证器等手段不断削减模型在控制回路中的决策职责，导致模型能力差异被掩盖；本文反其道而行，将模型作为唯一自变量，在固定智能体架构下评估其真实表现。 核心发现呈现"声明悖论"：小模型（2B-4B）往往比前沿模型更可靠地导航进入成功半径，却因过早声明到达或从未声明到达而失败——瓶颈不在飞行导航，而在对 prompt 中声明协议（特别是终止动作）的遵守能力。

Card 03 核心贡献

核心贡献

  • DroneCATS-Agent：一个模型无关的无人机智能体架构，定义了仅包含四种动作的指向式接口——go（点+深度）、rotate（偏航）、think（悬停思考）、finished（自声明到达），全部动作仅通过 prompt 声明，无需微调或函数调用 schema，任何 MLLM 均可直接插入。
  • 统一闭环协议与单一成功标准：整个 2×2 任务矩阵（目标是否移动 × 首帧是否可见）共用一条成功判据——以模型自身的到达声明为准，要求声明时处于目标 3D 距离 δ=5m 内且目标可见；不因单纯穿越目标区域而给分，使各任务列可比。
  • 覆盖 9 个模型的多维评测：4 个前沿 API 模型（GPT-5、Claude Opus 5、Gemini 3.7 Flash、Gemini Robotics-ER 2）、Qwen3.5 家族 4 个规模（2B/4B/9B/27B）以及具身特化模型 Cosmos3-Edge-2B，在 80 个单机情节和 20 个四机指挥情节上系统评测。
  • "声明失败"发现（Declaration Finding）：将小模型与前沿模型的差距定位为协议遵守能力而非导航能力——例如 Qwen3.5-2B 在 130% 起始距离处宣告到达，Cosmos3-Edge-2B 从不声明，而 Qwen3.5-9B 有 90% 情节进入成功半径却仅转化 35%。
  • 多无人机指挥评估首创：首次实现单一 MLLM 从多视角观测闭环控制多架无人机（N=4），并揭示单机表现排序不能迁移到指挥场景（GPT-5 指挥成功率 20%，Gemini 3.7 Flash 达 80%）。
Card 04 方法描述

方法描述

  • DroneCATS-Agent 闭环循环：每步输入仅包括自我中心单目 RGB 帧、指令和最近 5 个动作，模型输出一个 JSON 动作对象；go 动作返回归一化图像坐标（0-1000）与以米为单位的深度估计，由规则几何控制器将像素反投影为机体坐标系 3D 位移。
  • 动作设计：go 耦合视觉定位与前进；rotate（±90°/步）使视野外搜索可表达；think 将测试时推理计算化为悬停动作；finished 将终止权交给模型，由事后验证器判定声明是否成立，使智能体可被委派（composable）。
  • 执行层解耦：几何控制器负责坐标换算，飞行栈（速度-姿态-旋翼级联）负责连续跟踪设定点；模型责任止于 JSON 对象，所有模型共享同一套 prompt、解析器、控制器与情节运行器。
  • 多机指挥设置：当前帧槽位同时容纳全部 N 个视角（固定顺序），模型在单次响应中为每架无人机各输出一条命令，需自行区分视图对应的平台。
  • 成功判据算法：遍历按时间排序的到达声明，首个满足距离 ≤δ 且目标可见的声明即判定成功；附带的诊断指标包括 NE（导航误差）、最小距离、接近率、Oracle 成功率、声明的距离/起始距离比等。
Card 05 数据集与资源

数据集与资源

  • 仿真环境：基于 AirSim（Unreal Engine）构建；单机套件使用住宅区（residential）与校园（campus）两张地图，指挥套件使用住宅区地图与 Blocks（AirSim 自带几何环境）。
  • 情节规模：单机 4 类任务 × 每图 10 情节 × 2 图 = 80 个情节；N=4 指挥套件 20 个情节；共 100 个情节，每情节上限 300 秒。
  • 评估模型规模：Qwen3.5 家族（2B/4B/9B/27B）、Cosmos3-Edge-2B、GPT-5、Claude Opus 5、Gemini 3.7 Flash、Gemini Robotics-ER 2。
  • 推理资源：2B/4B 模型本地部署（vLLM，bfloat16，单张 H100）；Cosmos3-Edge-2B 配 32k 上下文占用 10.5 GiB，30-token 解码耗时 0.44s（约 2Hz）；更大模型经 API 访问。
Card 06 评估与结果

评估与结果

  • 评估基准与指标：以 δ=5m 的声明成功率（SR）为主指标，辅以 Oracle 成功率（OSR）、NE、声明率、接近率、声明距离/起始距离比；20 情节/单元，报告百分比；含三次飞行方差审计与逐模型失败分类。
  • 核心结果（单机，20 情节）：最佳模型接近任务成功率仅 65%（Gemini 3.7 Flash）；首帧不可见使最佳模型降至 40%，且无模型超过 40%；追击任务中 Gemini 3.7 Flash 达 80% 而 GPT-5 仅 15%，模型排序跨任务不稳定；Qwen3.5 系列成功率随规模单调（27B 33.8% → 2B 0%）。
  • 声明 vs 导航解耦：Qwen3.5-9B 有 90% 情节进入 δ 半径（高于所有前沿模型），但仅转化 35%，平均在起始距离的 63% 处声明；Qwen3.5-2B 在 128% 起始距离处声明、从不动身；Cosmos3-Edge-2B 进入半径 25% 且从不声明。
  • 多机指挥结果：GPT-5 指挥成功率仅 20%，Gemini 3.7 Flash 达 80%，单机排序不迁移；小模型常见失败模式为在不同视图间盲目复制同一坐标。
  • 具身特化无优势：Gemini Robotics-ER 2 四格平均 47.5%，低于通用 Gemini 3.7 Flash 的 57.5%，差距与随机波动相当；Cosmos3-Edge-2B 全任务零成功。
  • 失败归因结论：61/337 个未声明失败情节曾进入 δ 半径，若按轨迹邻近计分会将 182 个成功虚增三分之一；小模型的空间感知（grounding）尚可，但无法在长情节中维持声明协议并正确发出终止动作——"可部署边缘模型与前沿模型的差距不在导航，而在协议纪律"。
