TRIAGE: Efficient Vision-Language-Action Inference Needs Both Reuse and Pruning

02论文概述

  • 针对 VLA（视觉-语言-动作）模型在移动机械臂、人形机器人等搭载的嵌入式板卡（如 NVIDIA Jetson）上运行时，语言骨干网络的 prefill 延迟随每步数百个视觉 token 急剧增长、难以满足实时控制的问题
  • 指出现有免训练加速方法对未重算的 token 只采用单一策略（全部剪枝或全部复用），必然牺牲精度或浪费算力：剪枝丢弃缓存仍然准确的 token，复用则持续服务已过期的 KV 缓存
  • 通过 token 级诊断实验提出核心发现：非重算 token 应复用还是剪枝取决于其 drift（自缓存计算以来浅层 value 的相对变化量），与重要性无关——drift 低于阈值 0.3 时复用不劣于剪枝，超过 0.5 时复用产生最高 4.4 倍于剪枝的动作误差

03核心贡献

  • Token 级诊断：通过受控实验证明非重算 token 该复用还是剪枝取决于其 drift（而非 token 重要性），证明 prune-only 与 reuse-only 方法均非最优
  • TRIAGE 框架：提出三集合划分结构（重算/复用/剪枝），基于重要性与缓存有效性为每个 token 分配归宿，prune-only 与 reuse-only 是其两个极端特例
  • 固定重算预算机制：每步固定重算 B 个 token，预算 B 直接决定 prefill 延迟，使每步延迟有界（p99 仅高于均值 4%）
  • 实验表明 TRIAGE 在两个骨干网络与两个基准上平均成功率保持在全量重算 3 pp 以内，Jetson AGX Orin 上 prefill 延迟最多降低 48%
  • 在极小预算下优势显著：仅重算 7% 视觉 token 时，在 LIBERO-Object 上以 75.8% 成功率领先最强基线 24.4 pp

04方法描述

  • Drift 信号：定义 drift 为 token 在浅层（第 2 层）attention value 相对上次重算时的相对变化，因浅层对所有 token 每步都计算，该信号零额外开销；诊断实验标定阈值 δ=0.3，低于该值复用不劣于剪枝
  • 缓存有效性判定：缓存有效需同时满足已缓存、drift < δ、缓存年龄 ≤ T（T=10），决定非重算 token 复用还是剪枝
  • 重要性评估：采用浅层 attention 结合 SAFE-Pruner 的深层显著性预测（通过 patch 对应关系将首帧记忆迁移到当前帧），重要集合取 top B+κ 个 token
  • 三层预算分配：固定重算预算 B 依次分配给——维护（刷新最旧缓存）、强制重算（缓存失效的重要 token 优先）、可选刷新（缓存有效但变化快的重要 token）；其余 token 仅凭有效性决定复用或剪枝
  • 延迟可控：重算集合大小恒为 B，故 B 直接设定 prefill 延迟，部署时按控制环延迟目标选取

05数据集与资源

  • 基准：LIBERO 四个套件（Spatial/Object/Goal/Long，各 500 回合）、SimplerEnv Google Robot（Move Near、Pick Coke Can）
  • 骨干模型：OpenVLA-7B（256 视觉 token，自回归解码动作）、OpenVLA-OFT（双相机 512 视觉 token，单次前向预测 8 步动作块）
  • 硬件：延迟实测于 NVIDIA Jetson AGX Orin 与 RTX 3090（bf16 精度），每套件 250 次查询回放同一观测流
  • 基线：VLA-Cache、VLA-Pruner、SAFE-Pruner、SpecPrune-VLA（均为免训练方法）
  • 关键超参数：δ=0.3、T=10、μ=0.06、λ=1、κ=70；B=88（OpenVLA）/163（OFT）

06评估与结果

  • 评估指标：成功率、解析 prefill FLOPs、Jetson AGX Orin 与 RTX 3090 上的 prefill/E2E/p99 延迟
  • LIBERO：TRIAGE 平均成功率 73.7%（OpenVLA）与 95.8%（OFT），均在全量重算 3 pp 以内，且在所有设置中位于成功率-延迟 Pareto 前沿
  • 极小预算优势：LIBERO-Object 上仅重算 11% 视觉 token 时保持在全量重算 3 pp 内，7%（B=18）时达 75.8%，领先最强基线 VLA-Pruner 24.4 pp
  • 延迟收益：Jetson 上 prefill 延迟最多降低 48%（OFT 为全量重算的 0.52 倍），并在所有设置中 p99 延迟最低；p99 仅高于均值 4%，而 SAFE-Pruner 达 1.6 倍
  • SimplerEnv 迁移性：无需重新调参即达 54.5%（全量重算 54.8%），领先 SpecPrune-VLA 与 VLA-Pruner 4.2 与 6.1 pp
  • 局限性：超参数为经验设定而非理论推导；drift 阈值随骨干网络、任务与场景速度变化，需部署时自适应校准；未来可结合光流或运动向量在骨干运行前区分静态/动态区域
