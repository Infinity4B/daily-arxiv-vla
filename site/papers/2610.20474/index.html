02论文概述

  • 预训练的 视觉-语言-动作模型（VLA） 在未见过的长时程任务中经常中途失败，而现有的具身递归自我改进（RSI）方法要么只改进 harness（外壳/框架）而执行器权重冻结，要么盲目对所有失败进行微调。
  • 论文提出核心问题：自我改进的具身系统何时应该改变执行器的权重？答案在于对失败进行归因（attribution）。
  • 提出 AdaRSI 框架，仅在 harness 改进后仍然不可靠的子步骤上微调执行器，实现按需的递归自我改进。

03核心贡献

  • 形式化了具身智能体的按需递归自我改进（on-demand RSI）：将每个持续失败归因于 harness 或执行器，并据此决定是否改变权重，实例化为 AdaRSI。
  • 发现 harness 决定了训练是否值得：它吸收了本会被误判为需训练的错误，并设定了策略训练与调用时的起始状态。
  • 揭示微调能教会执行器缺失的动作，但也可能损害执行器本已擅长的子步骤，因此需要按需训练。
  • 在 RoboCasa365 全部 50 个目标任务上验证：无需任何人类示范，按需训练使预训练 VLA 在每个套件上均提升，且训练成本仅为全量微调的一小部分。

04方法描述

  • Harness 级改进：智能体（编码 agent）先编写工具与流程，在保留验证集上运行系统，并从执行反馈中迭代修改工具与过程。
  • 失败归因：在 harness 轮次后，记录仍失败但机器人已就位、指令已知的子步骤，判定为 executor-limited（执行器受限）子步骤。
  • 反事实重执行：通过保存/恢复模拟器快照，用不同指令或路径重试失败子步骤，区分「调用方式不当」与「执行器缺失的动作」。
  • 自采集示范：对基础执行器做拒绝采样，或编写读取特权状态的脚本专家生成标注数据（特权状态仅用于数据生成，部署时不可见）。
  • 微调与验证：每个示范集从 π₀ 或已有策略微调出子步骤策略，加入策略库 Π；在留存起始状态上验证，仅在实测有益的步骤中调用。
  • 跨轮次与跨任务递归：改进在轮次间累积，试点任务生成的经验文档与训练预算指导后续任务，实现"改进改进方式"。
  • 部署阶段：智能体遵循流程调用工具与策略，仅使用机器人常规观测，无快照、成功检查或特权状态。

05数据集与资源

  • 基准数据集：RoboCasa365 全部 50 个目标任务，分三个套件——18 个 Atomic-Seen、16 个 Composite-Seen、16 个 Composite-Unseen。
  • 任务规模：每个任务测试 50 个场景，开发/验证/测试场景互不相交。
  • 执行器模型：GR00T N1.5，组合任务使用官方 Composite-Seen 检查点，原子任务使用 Atomic-Seen 检查点。
  • 编码智能体：GPT-6.1-sol，通过 Codex 运行。
  • 训练资源：报告以 GPU 分钟统计（如 Composite-Unseen 上 AdaRSI 使用 966 GPU 分钟），不使用任何人类示范。

06评估与结果

  • 评估基准：RoboCasa365 官方协议，采用目标 split（厨房和物体与预训练不重叠）、官方任务时域与官方成功检查。
  • 对比系统：VLA（仅 π₀）、Agent + VLA、Agent + harness、AdaRSI，以及 Always train、Agent + weights 等消融变体。
  • 主要指标：每个任务的成功率（%），按套件对任务取平均。
  • 核心结果：

- 总体：AdaRSI 在三个套件均取得最高成功率，50 任务平均 48.8%，超过 VLA 的 42.4% 与 Agent + harness 的 46.7%。

- Composite-Unseen：成功率从 4.6% 提升至 13.8%，约为基线的三倍。

- Atomic-Seen / Composite-Seen：分别从 75.4%→79.7%、43.0%→49.0%。

- 成本优势：相比全量微调每个子步骤，AdaRSI 成功率略高，而 GPU 时间仅用 28%、自采集示范仅用 22%。

- 策略使用：Composite-Unseen 上 38 个策略中 32 个被使用，85% 训练时间投入被使用的策略；微调策略仅执行 15% 的操作步骤，而 Always train 为 71%。

- 配对测试：微调在 π₀ 缺失动作上提升显著（如打开微波炉门从 0/18 提升至 7/18），但在 π₀ 已擅长的动作上反而下降（如放置可颂从 16/40 降至 11/40）。

- 案例：WaffleReheat 从 harness 单独时的 0% 升至 AdaRSI 的 38%，由微调策略专门解决打开微波炉门这一瓶颈。
