02论文概述

  • 论文提出 ELMO（Emergent Latent-action MOdel），一个端到端的分层视觉-语言-动作（VLA）策略框架
  • 核心目标是解决现有潜在动作模型将动作块压缩为“运动码”（motion codes）而非“语义码”（semantic codes）的问题
  • 通过动态分层动作分块与观测条件下的解码器联合训练，ELMO 学习基于场景的语义动作表示（grounded semantic codes），使策略能捕捉行为意图而非仅复制运动学轨迹

03核心贡献

  • 提出 ELMO：将动态时间分块（H-Net 机制）与单阶段联合训练 VLA 规划器和观测条件解码器相结合，学习语义级动作表示
  • 系统分析现有潜在动作方法（如 MINT、EDAR、FAST），通过线性探针和 t-SNE 揭示其潜在空间主要编码运动学而非任务语义
  • 引入 Blocks 基准：一个消除捷径（spurious shortcuts）的双臂 ALOHA 仿真基准，用于严格评估语言指令 grounding 与泛化能力
  • 在 LIBERO、LIBERO-Plus、CALVIN 等标准基准上取得领先，并在 Blocks 上以 38.6% vs 基线 <5% 的成功率展示出极强泛化优势
  • 在真实双臂 ALOHA 机器人上验证 sim-to-real 迁移：push 13/25、placement 8/25 成功

04方法描述

  • 动态分块与路由：递归状态编码器输出隐状态，路由器通过相邻步余弦相似度判断是否开始新的动作块（boundary），从而将轨迹分割为可变长度语义段
  • 分层结构：高层 VLA 规划器仅在边界步运行，利用多视角视觉与语言 token 预测连续语义码 \(z_k\)；低层动作策略在每一步结合当前语义码、编码器状态和手腕相机反馈，通过 flow matching 生成动作窗口
  • 端到端单阶段训练：同时优化编码器、路由器、规划器、解码器与动作头，视觉骨干（SmolVLM2）冻结
  • 边界加权 flow matching：对边界步预测的动作窗口给予更高权重（\(\alpha=4\)），确保语义码更新传递有效梯度
  • 路由器正则化：使用目标压缩比损失和早期运动学启发式 warm-start，引导边界与接触事件对齐
  • 历史正则化：通过轨迹拼接（splicing）打破轨迹连续性，避免策略依赖历史记忆；采用 onset-prioritised sampling 集中训练难以正确起始的任务

05数据集与资源

  • 标准仿真基准：LIBERO（Spatial、Object、Goal、LIBERO-10）、CALVIN（ABCD→D 长时程）、LIBERO-Plus（零样本扰动鲁棒性）
  • 自建基准 Blocks：双 ViperX 臂、三 RGB 相机、五色方块随机放置，包含 10,000 条 scripted 演示和 2,500 条恢复轨迹
  • 真实机器人：双机械臂 ALOHA 平台，利用仿真 checkpoint 微调 10k 步，30 条人类演示/任务组合
  • 模型规模：视觉骨干使用 SmolVLM2；ELMO 可训练参数约 22M（编码器、路由器、规划器动作头、解码器），对比 SmolVLA 动作头约 100M
  • 训练资源：论文未明确列出 GPU/TPU 型号或数量；主要提及 CALVIN 消融训练 16,000 步、3 个随机种子

06评估与结果

  • 评估环境：LIBERO、LIBERO-Plus、CALVIN、Blocks 仿真和真实机器人，均采用闭环评估
  • 主要指标：任务成功率（%）、CALVIN 平均连续完成子任务数、Blocks ID/OOD 成功率
  • LIBERO：ELMO 平均成功率 90.2%，与 MINT-30M（使用图像增强）持平，优于 SmolVLA、SmolVLA+FAST、SmolVLA+EDAR
  • LIBERO-Plus：ELMO 达到 64.0% 零样本成功率；在不使用图像增强的方法中比次好方法高 9.6 个百分点
  • CALVIN ABCD→D：ELMO 平均完成 4.08 个连续子任务，比 SmolVLA+FAST 高 +0.75
  • Blocks：ELMO 获得 38.6% ID、31.7% OOD 成功率，所有基线均低于 5%，证明其语言 grounding 和泛化能力
  • 真实机器人：push 任务 13/25、placement 任务 8/25，大幅优于 SmolVLA（2/25、0/25）
  • 消融实验：去除路由器 warm-start 使边界与抓取事件对齐率从 82% 降至 39%；去除手腕交叉注意力或 skip connection 分别降低平均完成子任务 1.05 和 0.58；固定分块替代动态路由导致性能下降（4.04→3.89）
