02论文概述

  • 论文对世界-动作模型 Cosmos Policy 在 RoboCasa 仿真环境中的推理时扩展（test-time scaling）进行实证审计，而非提出新规划器
  • 核心问题：额外推理计算是否真正改善控制，需验证三大前提——候选选择信号是否可用、名义计算节省是否转化为端到端加速、评估过程是否可靠
  • 审计发现：价值选择器表现不如随机选择、token 剪枝的 FLOPs 节省未达到实际加速目标、评估栈中存在与推理计算量相关的静默渲染损坏

03核心贡献

  • 提出 premise-first、预注册的审计方法论，将 test-time scaling 作为“前提链”而非单一成功率来评估
  • 通过 因果消融 + hindsight oracle + power gate + framebuffer sentinel，区分负结果、不确定结果和无效测量
  • 实证揭示在测试配置下，best-of-N 候选选择缺乏可利用信号，部署价值选择器比随机选择更差
  • 证明 token 剪枝的 名义 FLOPs 节省不能简单等同于端到端 wall-clock 加速
  • 识别并修复 RoboCasa/robosuite 栈中的 静默渲染损坏，并发布检测器、修复和复现脚本

04方法描述

  • 使用 snapshot replay 评估闭环成功率：恢复状态、执行候选动作块，并在固定 base policy 下继续 rollout
  • 对同一查询状态重放 N=8 个候选，比较 value selector、random selection 和 hindsight oracle，估计选择 headroom
  • 使用 预注册决策阈值 和 power gate：从 smoke sample 估计 paired-residual 标准差，预测置信区间半宽，未达阈值则不启动完整实验
  • 对完整 query 进行 eager 端到端计时，区分 deployed path 和 decode-excluded path，比较 dense 与 token pruning 的实际延迟
  • 使用 framebuffer sentinel 预填充渲染目标，检测渲染损坏；配对运行 bug-present 与 render-fixed 进行对照

05数据集与资源

  • 数据集/环境：RoboCasa 仿真框架（基于 robosuite），涉及任务包括 PnPCounterToMicrowave、PnPMicrowaveToCounter、PnPStoveToCounter、TurnSinkSpout、TurnOnStove 等
  • 模型：nvidia/Cosmos-Policy-RoboCasa-Predict2-2B，约 2B 参数，bf16 权重，latent shape [1,16,11,28,28]，11 个 latent frames × 196 tokens = 2156 tokens，每次查询 5 步去噪
  • 计算资源：单张 NVIDIA RTX A6000，PyTorch 2.7.0，CUDA 12.8，eager 后端，batch size 1；论文未涉及训练 GPU/TPU 集群
  • 资源发布：framebuffer-sentinel 检测器、OpenGL 上下文修复、复现脚本和预注册审计协议

06评估与结果

  • 候选选择：价值选择器比随机选择低 1.66 pp（state 95% CI [-2.97,-0.31]；episode CI [-2.49,-0.71]）；hindsight oracle 仅提升 +1.40 pp（episode CI 含 0），82% 的状态所有候选结果完全相同，ICC 仅 0.20
  • 自适应计算：token pruning 每前向 FLOPs 最多降低 47.9%，但完整 query 的 deployed path 端到端加速最高仅 1.152×，decode-excluded path 为 1.253×，均未达到 1.5× 目标；joint allocation 效应低于噪声底，power gate 未通过，结论为 inconclusive
  • 评估可靠性：官方直接策略路径渲染损坏率为 0.67%（8/1200，bug arm）；修复后 200 个配对 episodes 成功数从 102 提高到 105（+3，且全部为失败→成功）；在计算密集的 planning mode 下损坏率可升至 65%，但官方直接策略成绩基本不受影响
