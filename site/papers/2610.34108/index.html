Card 03 核心贡献

核心贡献

  • 提出 RoboDuo 双系统框架，使用代码（而非 token 或 latent vector）作为慢决策系统与快执行系统之间的接口；当完整任务 VLA 失败时，由原子 VLA 接管剩余步骤，且控制权不再返回完整任务 VLA。
  • 从 LIBERO 演示中自动构建 LIBERO-Atomic、LIBERO-Code 和 LIBERO-Judge，分别训练原子 VLA、coding agent 和完成检查器。
  • 在 X-VLA 和 π₀.₅ 两个冻结的完整任务 VLA 上实例化 RoboDuo，无需更新其权重；在 LIBERO、LIBERO-PRO 和真实机器人上均取得提升，且增益集中在长时程任务上。
  • 证明“先完整尝试、失败后原子恢复”的程序结构优于从头分解任务的 code-as-policy 方法。
Card 04 方法描述

方法描述

  • 双系统执行：coding agent 生成一个两层程序；Layer 1 调用 vla_execute_fulltask 让完整任务 VLA 尝试整个任务，随后用 is_task_complete 检查结果；若失败，Layer 2 遍历原子计划，每步由原子 VLA 执行，最多重试 3 次，直到该原子子目标满足。
  • 原子动作分割：使用行业 VLM（Doubao Seed 2.1 Pro）对 LIBERO 演示视频进行标注，通过规则后处理将演示切割为 effect-complete 的原子片段，每条原子指令对应一个完整技能（如 move_to_and_grasp black_bowl）。
  • 三个模块的训练：原子 VLA 在 LIBERO-Atomic 的短片段上训练，与所选 backbone 同架构；coding agent 通过最大化目标程序似然（完整尝试优先、失败后原子恢复）微调；completion check 作为视觉语言分类器，判断给定子目标在当前观测中是否成立。
  • 关键创新点：coding agent 不直接产生动作，只决定何时调用哪个 VLA、下发什么指令，从而保持 VLA 的推理速度；代码接口天然支持条件判断、重试循环和控制权切换。
Card 05 数据集与资源

数据集与资源

  • LIBERO 四个评测套件（Spatial、Object、Goal、Long）和 LIBERO-90。
  • LIBERO-Atomic：覆盖 125 个任务，包含 9,214 个原子片段和 5,442 个程序；评测中五类原语共调用 21,771 次。
  • 冻结的完整任务 VLA：X-VLA 和 π₀.₅。
  • coding agent 和 completion check 基于 Qwen3.5-2B 微调。
  • 原子 VLA 训练资源：8 块 NVIDIA A800 GPU；训练步数 X-VLA 为 100k 步、π₀.₅ 为 30k 步。
  • 评测设置：每任务 50 次试验，重试预算 N=3。
Card 06 评估与结果

评估与结果

  • 评测环境与基准：在 LIBERO 四个套件、LIBERO-PRO（位置扰动 S 和任务扰动 T 的 8 列）以及真实机器人（三种水果摆放布局）上进行闭环任务成功率（%）评测。
  • LIBERO 结果：在四套件训练下，RoboDuo 将 X-VLA 平均成功率从 95.25% 提升到 96.40%（Long 上 87.4→91.6），将 π₀.₅ 从 97.25% 提升到 98.40%（Long 上 93.6→96.2）；RoboDuo+π₀.₅ 在四套件训练下的平均 98.40% 已略高于五套件训练下 π₀.₅ 的 98.30%。
  • LIBERO-PRO 结果：RoboDuo 将 π₀.₅ 的平均成功率从 32.05% 提升到 39.33%，其中最大增益在 Object-T（25.2→55.8）；五套件训练下平均从 43.58% 提升到 45.68%。
  • 真实机器人结果：RoboDuo 将成功率从 36.7% 提升到 53.3%，且无需更新冻结的完整任务 VLA。
  • 消融实验：对比不同 coding agent（无 agent、LIBERO-Code 微调、GPT、GPT+TAMP），表明 LIBERO-Code 微调的 agent 在 Object-T 等长时程任务上表现最佳，GPT+TAMP 在部分列上略优但整体接近。
