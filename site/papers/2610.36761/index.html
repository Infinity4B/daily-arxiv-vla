02论文概述

  • 针对自动驾驶实验室（Self-Driving Laboratories, SDLs）中灵活机器人控制与实验室仪器类型化 API、连续测量数据难以整合的执行接口挑战
  • 提出一个可追溯的统一框架，包含四个组件：LAM、OpenSDL、Safe-SDL 和 L3-Bench，连接混合动作生成、受监控的设备执行、测量反馈与实验评估
  • 解决 SDL 工作流中的协调与可追溯性问题，使实验过程（从模型提案、安全门控到设备执行）完全可审计、可回放

03核心贡献

  • LAM（Lab Action Model）：提出测量条件化的策略架构，扩展视觉-语言-动作（VLA）范式，同时生成连续机器人轨迹和类型化仪器 API 调用（混合动作空间）
  • OpenSDL：统一执行基础设施，将角色级操作映射到异构设备，按依赖关系协调执行，并记录带时间戳的因果事件账本
  • Safe-SDL：运行时安全门控，结合调度前的模式与资源检查，以及执行期间（含长时间等待期）基于信号时序逻辑（STL）的安全监控
  • L3-Bench：规定 episode 级评估协议，涵盖物理结果、时序、可复现性、安全违规和故障恢复五个维度
  • SDL-Traj：提出与 PROV-O 对齐的实验室溯源档案，复用核心溯源关系并增加设备能力、单调时钟元数据与 STL 鲁棒性等专用术语

04方法描述

  • 将实验室过程建模为 POMDP，动作空间为连续机械臂轨迹与离散仪器调用的笛卡尔积 A = A_arm × A_inst，两类动作共享时间基准与事件账本
  • LAM 由三个模块组成：约 3B 参数的多模态上下文骨干（VLM）、约 300M 参数的连续运动专家（采用 flow matching，借鉴 π0 的 VLA 运动建模）、以及生成 Role–Op–Parameters 类型化调用的离散函数调用头
  • 训练目标为混合损失：flow matching 损失 + 交叉熵调用监督 + 可选测量预测损失；采用保持量纲的固定缩放遥测编码器
  • OpenSDL 初始实现包含 Rust 控制引擎、MQTT/串口/TCP 传输、ESP32 桥接和 SQLite 存储；采用 Role/DeviceProvider 语义抽象与六类生命周期事件（proposal、gate、dispatch、acknowledge、complete、compensate）
  • Safe-SDL 对温度、接触力、避障距离等约束施加 STL 规范，计算带符号时间鲁棒度，低于阈值即触发动作阻塞与安全降级或安全中止；运行时状态机含七个状态
  • 采用 L1–L4 自主性分级，聚焦近期可实现、可测量的 L3（测量条件化适应）行为

05数据集与资源

  • 未使用公开大规模数据集；训练/校准/测试数据按完整实验批次分组策划，设备迁移测试在训练时保留目标 provider
  • 计划中的版本化场景/几何资产集 Clean-3D 用于种子化数字孪生回放
  • LAM 目标规模：约 3B 参数骨干 + 约 300M 参数运动专家；模型训练尚未完成
  • 执行基础设施基于 Rust 控制引擎与 ESP32 硬件桥接；论文未报告具体 GPU/TPU 训练资源

06评估与结果

  • 提出 L3-Bench 评估协议：以完整 episode（从任务提交到完成、回滚或安全终止）为基本统计单元，采用 bootstrap 置信区间与批次级聚类
  • 主要指标：归一化物理产率 Y、时间安全违规率 SVR、运营时间成本 C；诊断指标包括质量转移误差 Δm、分液均匀度 CV、温度控制误差 ITAE、makespan 与恢复时间
  • 预设四种评估条件：标称运行、测量漂移、设备迁移（RQ1–RQ4 对应测量条件化收益、并发调度提速、门控容错恢复、角色保持设备替换）
  • 重要说明：本文为框架/提案性质论文，端到端 LAM 训练、跨设备迁移实验及系统性硬件与安全验证均尚未完成，吞吐量、适应性与故障恢复的提升目前为待验证假设，尚无实验结果
