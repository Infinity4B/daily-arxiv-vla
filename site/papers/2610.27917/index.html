EventSync: Event-Driven Memory Updates for History-Dependent Manipulation

02论文概述

  • 论文针对历史依赖性机器人操作任务，提出 EventSync 层次化框架，解决当前观测不足以决定下一步动作、需要结合任务上下文与交互历史的问题
  • 核心思想是通过 事件驱动的内存更新 协调高层任务推理与低层动作执行，避免因过早记录子目标完成而导致任务进度错误
  • 在 RoboMME 仿真基准上取得 64.5% 总体成功率，超过最佳基线 20.0 个百分点；在四个真实机器人任务上也验证了有效性

03核心贡献

  • 提出 EventSync 层次化内存框架：高层 Memory Reasoner 管理任务内存并生成子目标，低层 Action Executor 执行动作，独立的轻量 Event Monitor 提供完成反馈
  • 设计 事件驱动任务内存更新机制：轻量 Event Monitor 结合视觉观测与末端执行器轨迹评估操作完成，以完成证据触发已完成子目标历史的更新和后续高层推理
  • 在 RoboMME 仿真基准和 四个真实机器人任务 上进行系统评估，验证事件驱动内存更新在历史依赖性操作中的有效性

04方法描述

  • Memory Reasoner 基于 Qwen3-VL-4B-Instruct 微调，结合任务计划、已完成子目标历史、当前图像和视觉历史生成空间锚定的子目标
  • Action Executor 基于 π0.5 视觉-语言-动作模型微调，接收子目标、当前观测和可选视觉历史特征，生成动作块
  • Event Monitor 使用冻结的 DINOv2-Base 视觉编码器提取视觉 token，融合末端执行器轨迹 token，通过两层 Transformer 同时预测操作完成概率和事件增量；总参数 87.39M
  • 事件驱动的更新策略：仅当 Event Monitor 提供完成证据时，才将当前子目标加入已完成历史并触发 Memory Reasoner 推理下一个子目标

05数据集与资源

  • 仿真基准：RoboMME 的 16 个历史依赖任务，涵盖 Counting、Permanence、Reference、Imitation 四类，每任务 50 回合
  • 真实机器人任务：SwingXTimes、UnmaskCube、ImagePickPlace、SequencePickPlace，分别对应四类内存需求；训练轨迹数分别为 90、90、150、150 条
  • 模型规模：Memory Reasoner 约 4B 参数；Event Monitor 87.39M 参数（含视觉编码器）；Action Executor 基于 π0.5 微调
  • 训练资源：使用 NVIDIA H100 GPU；Memory Reasoner 用 LoRA（rank 16）微调 2 个 epoch，执行器在仿真数据上训练 80,000 步、真实数据上 20,000 步

06评估与结果

  • RoboMME 仿真结果：EventSync（带 FrameSamp+Modul 视觉历史执行器）总体成功率 64.5%；无视觉历史执行器版本 62.0%，均显著优于基线（π0.5: 17.9%，GroundSG + QwenVL: 32.7%，MemER: 42.4%，FrameSamp+Modul: 44.5%）
  • 在 SwingXtimes 任务上，无视觉历史执行器的 EventSync 达到 94.0%，比 GroundSG + QwenVL 的 7.3% 提升 86.7 个百分点
  • 事件驱动更新相比固定 1:1 调度，成功率提升 6.5 个百分点，高层调用减少 70.8%，平均回合时间减少 40.1%（从 78.09s 降至 46.74s）
  • 真实机器人结果：EventSync 在四个任务上均获得最高成功次数（SwingXTimes 9/10、UnmaskCube 7/10、ImagePickPlace 9/10、SequencePickPlace 7/10），尤其 SwingXTimes 从无 Event Monitor 的 0/10 提升至 9/10
  • 消融实验显示：移除 Event Monitor 轨迹输入导致成功率下降 2-3 个百分点；移除高层在线视觉历史导致成功率下降 10-12 个百分点；结构化事件预测训练目标带来约 4-6 个百分点提升
