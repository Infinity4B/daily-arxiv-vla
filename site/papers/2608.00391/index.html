02论文概述

  • 论文聚焦视觉-语言-动作（VLA）模型的训练无关令牌跳过（training-free token skipping）技术，研究其在闭环机器人控制中的可靠性问题，核心发现令牌跳过的可靠性由门控（gate）的信号来源（provenance）决定，而非跳过机制本身
  • 现有令牌跳过方法在闭环场景下，若门控从稀疏前向传播（即self-harvested自收获门控）获取，会发生静默失败（silent failure），且现有动作级检测器无法有效识别该失败，导致任务成功率大幅下降
  • 论文目标是解决自收获门控导致的令牌跳过性能崩溃问题，在不增加推理关键路径延迟的前提下提升闭环VLA的可靠性

03核心贡献

  • 隔离变量验证：通过控制实验交叉验证门控来源与跳过机制（缓存复用reuse、直接删除deletion）对闭环可靠性的影响，证明门控来源是区分可靠与不可靠跳过的核心因素，而非跳过机制本身
  • 提出actuation-slack refresh方法：在机器人执行当前动作块的执行间隙（actuation slack，约400ms的空闲窗口）内运行一次密集前向传播（不输出动作），为下一个控制步提供干净的门控信号，同时为缓存复用机制提供新鲜KV缓存基座，将两种跳过机制在LIBERO-Object上0.9跳过比下的成功率从0.68（reuse）和0.31（deletion）恢复到0.98
  • 全场景修复性能崩溃：将该方法集成到VLA-Cache、VLA-Pruner等主流缓存和剪枝方法中，可在2种VLA策略、4个LIBERO套件、4个SIMPLER任务上修复所有由自收获门控导致的性能崩溃，同时服务延迟比密集推理低18-22%
  • 解释现有方法性能边界：该框架可解释已发布方法的性能限制，例如VLA-Cache的浅层重计算仅能部分修复问题，VLA-Pruner在特定条件下可避免门控来源失败的原因

04方法描述

  • 首先通过控制变量实验隔离令牌跳过的两个核心变量：一是跳过机制（reuse缓存复用、deletion直接删除），二是门控来源（self-harvested自收获门控、clean干净门控），在相同测试场景下交叉验证两者的独立影响
  • 提出的actuation-slack refresh（执行间隙刷新）方法属于训练无关方案，无需重新训练基座模型：利用VLA策略的推理-执行交替特性，在机器人执行当前动作块、推理GPU空闲的窗口内运行一次密集前向传播，其动作输出被丢弃，仅保留完整的视觉令牌注意力结果作为下一个控制步的干净门控信号，同时为缓存复用场景提供未受稀疏前向干扰的新鲜KV缓存基座
  • 该方法采用无条件刷新策略（每执行一个动作块就触发一次刷新），无需依赖失败检测触发机制，且密集前向传播在动作执行的关键路径外运行，不增加服务延迟
  • 创新点：首次明确门控来源是闭环VLA令牌跳过可靠性的核心决定因素，利用动作执行的空闲窗口零延迟代价地提供干净信号，解决了自收获门控导致的现有方法无法检测的静默失败问题

05数据集与资源

  • 使用的数据集：LIBERO基准（包含Spatial、Object、Goal、Long四个机器人操作任务套件）、SIMPLER基准（包含pick-coke、move-near、drawer、put-in-drawer四个Google Robot仿真任务）
  • 模型规模：采用7B参数的OpenVLA-OFT策略、CogACT-Base策略作为基座模型
  • 评估资源：仿真评估使用H100、RTX 4090 GPU；物理机器人验证使用RTX 5880 Ada GPU，搭配AgileX Piper机械臂与Intel RealSense D455相机

06评估与结果

  • 评估环境：LIBERO仿真环境、SIMPLER仿真环境、AgileX Piper物理机器人平台
  • 主要评估指标：任务成功率、关键路径服务推理延迟
  • 关键实验结果：

- 在LIBERO-Object任务、0.9跳过比下，自收获门控会导致reuse机制成功率从密集推理的1.00降至0.68，deletion机制降至0.31；现有动作级检测器的早期预警AUROC仅为0.45-0.65，全episode AUROC的0.80是时长偏差导致的假象，条件化后仅0.26-0.44，无法可靠识别该静默失败

- 提出的actuation-slack refresh方法可将两种机制的成功率恢复至0.98，在4个LIBERO套件、4个SIMPLER任务上修复所有由自收获门控导致的性能崩溃

- 延迟表现：H100上关键路径服务延迟为52.0ms，比密集推理（63.4ms）低约18%；物理机器人平台上服务延迟为98.1ms，比密集推理（125.6ms）低21.9%

- 对比触发式刷新方法SAFE-Pruner，其自收获触发机制在LIBERO-Object的3222次编码中仅触发3次，任务成功率仅0.19，而无条件刷新的方法成功率达0.98；即使使用oracle触发，也无法同时实现高成功率和低延迟
