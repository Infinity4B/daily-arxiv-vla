Recover, Don't Just Continue: Learning from Feedback for Physical Failure Understanding and Correction

01研究单位

  • 论文作者均来自 浙江大学（Zhejiang University），隶属于 ZJU ACES Lab 的 OmniAI Group。
  • 第一作者 Miao Pan 和 Kaixiang Yao 为共同贡献者。

02论文概述

  • 论文研究如何让多模态大语言模型从“会做规划”进化成能理解物理交互、适应执行能力并在失败后纠正行为的具身智能大脑。
  • 核心问题：物理执行中动作会偏离预期效果，且能被实现的内容受本体、控制器和环境共同约束；当前具身基础模型缺乏物理因果理解与失败定位、执行能力识别与适配、基于交互经验的上下文学习三项互补能力。
  • 提出 Embodied-Corrector，通过受控失败-恢复数据、评估优先训练和 OPD 内化，让模型在固定执行后端下实现失败原因分析与可执行纠正。

03核心贡献

  • 识别出物理因果理解、执行能力适配、从交互反馈中上下文学习三项互补且不可替代的纠正能力，并诊断当前多模态具身大脑缺失这些能力。
  • 提出 Embodied-Corrector 及受控失败-恢复数据构建流程，将动作、可观测物理后果、失败原因与可执行恢复对齐为 Judge–Cause–Sub–Fine 监督信号。
  • 提出评估优先 SFT（evaluation-first SFT）与OPD（On-Policy Distillation）内化，解决前缀分布不匹配与响应级奖励过粗问题；设计噪声感知非对称 OPD（NEPO）。
  • 在脑级失败推理、固定后端执行（冻结 VLA 与 GPT-5.5 代码生成器）以及真实机器人上验证，展示失败解释、指令适配与纠正上下文能力。

04方法描述

  • 受控失败数据构建：从成功轨迹的子任务边界注入单一受控扰动（导航、可达性、抓取姿态、控制时机、关节状态、任务前提、目标 grounding），重放并仅保留可观测且可恢复的失败，生成纠正轨迹。
  • 训练目标字段：Judge 判断当前子任务是否完成；Cause 基于可观测证据定位失败原因；Sub 决定推进或重做当前子任务；Fine 给出动作、目标参数、顺序与验证步骤。
  • 评估优先训练：先训练 Judge/Cause，再在准确 Judge/Cause 前缀下训练 Sub/Fine；之后采用 OPD 在自生成前缀下生成规划，并用准确前缀的对比前向概率差异作为 token 级信号进行强化/抑制。
  • NEPO：根据自生成分布的熵动态门控负信号，正信号保留、负信号随熵衰减，提升训练稳定性。
  • 推理阶段：纠正 Harness 将目标、观测、执行历史与检索记忆结合生成工作流代码或调用冻结 VLA；执行后由 Embodied-Corrector 输出 Judge/Cause/Sub/Fine，仅环境验证后写入 episode memory。

05数据集与资源

  • 从 RoboCasa365 和 OmniBehavior 成功轨迹构建受控失败-恢复数据，并保留 held-out 轨迹构建 EmbodiedDiag-Bench。
  • 基础模型规模：RynnBrain-8B、RoboBrain2.5-4B、InternVL3-8B、MiMo-Embodied-7B、Qwen2.5-VL-7B 等；对比模型包括 GPT-5.5、GPT-4o、Claude-3.7-Sonnet、Qwen3-VL-32B。
  • 训练/推理使用模拟环境与机器人执行接口；部分对比使用 GPT-5.5 代码生成器和冻结 VLA；真实机器人验证使用 Piper 平台。
  • 模型变体：RynnBrain-SFT、RynnBrain-OPD、RynnBrain-GRPO、RynnBrain-NEPO。

06评估与结果

  • EmbodiedDiag-Bench：NEPO 模型在导航/操作上 Judge 准确率 79.6% 和 81.2%，Cause 准确率 58.2% 和 54.6%，Sub/Fine 至少 63.7%，超过 SFT/OPD/GRPO。
  • EB-ALFRED 迁移：NEPO 在所有六个子集上优于基础模型；相比 SFT，在 Complex/Spatial/Long 任务上增益最明显。
  • 代码执行（无 VLA，固定 GPT-5.5 代码生成器）：NEPO 与固定代码执行结合，在 OmniBehavior 和 LIBERO-PRO 上提升所有十种执行条件，宏平均增益 13.9 个百分点。
  • 冻结 VLA 执行：执行感知分解在 Composite-Seen 和 Composite-Unseen 上分别提升 5.4 和 6.1 个百分点。
  • 真实机器人验证：在 Piper 平台上验证具身纠正能力（具体成功率见附录 G）。
  • 反馈形式消融：与重复失败结果相比，提供失败原因可一致提高任务成功率（例如 0.22→0.28，0.20→0.27，0.20→0.24）。
