02论文概述

  • 论文提出了 VLA-HWBench，一个系统刻画视觉-语言-动作（VLA）模型在边缘设备上完整“观测到动作”推理路径的基准测试
  • 旨在解决三个研究空白：现有研究覆盖的动作生成方式太少、阶段划分过粗（最多三阶段）、未在相同模型上公平比较推理优化方法
  • 回答三个核心问题：推理时间花在哪里（Q1）、优化带来多少收益以及时间如何转移（Q2）、优化后剩余时间受什么限制（Q3）

03核心贡献

  • 构建 VLA-HWBench 基准，覆盖 18 个开源 VLA 模型（19 个参考配置），涵盖全部四种动作生成形式（流匹配、并行解码、自回归 token、先推理后动作）
  • 提出七阶段延迟分解方法（CPU 预处理、主机-设备拷贝、视觉编码、预填充、动作生成、后处理、残余开销），首次计时 CPU 预处理阶段
  • 在相同模型上系统比较编译优化、专用后端（TensorRT、FlashRT）和低精度量化（FP8/NVFP4）的收益
  • 揭示三项关键洞察：延迟由动作生成迭代次数决定而非模型大小；核融合+4-bit 权重优化收益最大但覆盖有限；优化后无单一资源构成瓶颈
  • 为边缘 VLA 的模型设计、推理软件和硬件选型提供可操作的设计指导

04方法描述

  • 将每次推理调用分解为 S0–S6 七个阶段（T = ΣT_k），在阶段边界同步计时，并通过 CUDA graph 内核切分图内阶段
  • 动作生成建模为 T₄ ≈ N·t，其中 N 为去噪步数/生成 token 数/推理 token 数，揭示延迟主要由迭代次数决定
  • 采用三组指标：阶段占比与每动作推理时间（T/H）、优化加速比（T₀/T）、基于 Roofline 模型的瓶颈分析（计算边界 F/P 与内存边界 W/B）
  • 设计原则：一致的运行时后端（各模型使用其官方 LIBERO 评估代码与依赖版本）、阶段级时间归因、双边缘平台（Arm + x86 主机）分离主机/GPU/内存影响
  • 优化实验在 π₀.₅ 和 GR00T N1.7 上逐级启用：torch.compile 编译 → FlashRT/TensorRT 专用后端 → FP8/NVFP4 低精度，每次只改变一个因素

05数据集与资源

  • 18 个开源 VLA 模型：涵盖流匹配（π₀.₅、GR00T N1.7、SmolVLA、X-VLA 等 10 个）、并行解码（OpenVLA-OFT、VLA-Adapter 等 4 个）、自回归 token（pi0-FAST、VLA-0 等 3 个）、先推理后动作（DeepThinkVLA、MolmoAct2-Think 等 2 个），参数量 0.45B–7.99B
  • 输入采用统一的 LIBERO-10 真实观测（两路 256×256 相机图像、机器人状态、任务指令）
  • 平台 1：NVIDIA Jetson AGX Thor（Blackwell GPU 2560 CUDA 核心、14 核 Neoverse CPU、128GB LPDDR5X 273GB/s、FP16 258 TFLOP/s）
  • 平台 2：AMD Ryzen AI Max+ PRO 395（RDNA 3.5 GPU 40 CU、16 核 Zen 5 CPU、128GB LPDDR5X-8000 256GB/s、FP16 59.4 TFLOP/s）
  • 软件栈：LeRobot 0.6.1、PyTorch 2.11/2.14、CUDA 13.2 / ROCm 7.2；测试协议为每配置 20 次预热 + 最多 100 次计时调用，报告中位数延迟

06评估与结果

  • Q1（时间去向）：Jetson 上 19 个配置中 14 个以动作生成为最大阶段；延迟跨 77ms–6.3s（82×）和 114ms–17.9s（157×）；仅 10 个（Jetson）和 9 个（AMD）配置能跟上 LIBERO 20Hz 控制（T/H < 50ms）；对数延迟-对数参数量拟合最多解释 15% 方差，延迟实际跟随动作生成迭代次数
  • Q2（优化收益）：编译、专用后端、低精度使 π₀.₅ 依次加速 2.5×、1.8×、1.6×（共 7.2×，318ms→44ms），GR00T N1.7 共 2.6×（119ms→46ms）；核融合+4-bit 后端（FlashRT）收益最大但仅支持这两个模型且仅在 Jetson 上；优化使时间转移至缩短最少的阶段（GR00T N1.7 CPU 预处理从 12% 增至 39%）
  • Q3（瓶颈分析）：优化后无单一资源构成瓶颈——Jetson 上少 token 阶段（去噪步）受内存带宽限制（已达峰值带宽一半以上），视觉编码与预填充受软件限制（未融合内核，仅达硬件上限的 6–42%），CPU 预处理受串行 Python 与线程唤醒限制；AMD 平台上仅存在编译优化，使平台差距从 2.0–2.5× 扩大到 5.7–7.8×
  • 设计建议：边缘 VLA 应减少动作生成迭代次数而非缩小模型；推理软件应将核融合与低位宽执行扩展到更多模型和平台；边缘硬件应优先考虑内存带宽和快速主机 CPU 而非峰值 GPU 算力
