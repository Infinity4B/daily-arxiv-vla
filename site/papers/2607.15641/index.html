Card 03 核心贡献

核心贡献

  • 提出 IMBench 基准：35 个基于 robosuite 的机器人操控任务，测试模型是否理解物理并能将其转化为动作，揭示当前基础模型和 learned policies 的失败点
  • 发布数据集与工具：约 14K 条过滤轨迹及可扩展的场景生成脚本，支持直觉性操控的可复现研究
  • 形式化直觉性操控的 Understand–Infer–Act 分解框架，结合三阶段 VLM 评估协议（约束理解→计划生成→执行）和闭环策略回滚，系统测量当前模型的“理解-执行鸿沟”
Card 04 方法描述

方法描述

  • 基于 robosuite 仿真平台构建任务，采用 Gymnasium 风格接口和固定种子重置
  • 任务围绕推理瓶颈（inference bottleneck）设计，包括几何约束、动力学预测、因果链、工具使用、隐藏状态、主动发现、反应式重规划、稳定性平衡等 7 大类别
  • 三阶段评估框架：

- Stage 1（理解）：使用 VLM（GPT-5.5, GPT-5.4-mini, Gemma-4, Claude Haiku-4.5, Claude Sonnet-4.6）通过 ReAct 框架提取物理约束

- Stage 2（推理）：VLM 生成高层子目标计划序列（如 Grasp, Slide, Toss）

- Stage 3（执行）：采用 ReAct（Reasoning + Acting） 闭环框架，以 GPT-5.5 作为 IMBAgent 执行动作基元，结合多视角图像、本体感知和力/扭矩信号进行迭代反馈

  • 端到端视觉运动策略评估：包括 Diffusion Policy、π₀.₅ 和 GR00T N1.5 的零样本和微调版本
  • 演示数据通过三阶段过滤流程确保质量：人工标注（1-5 分筛选，保留 ≥4 分）→ VLM 自动异常检测 → 人工最终验证
Card 05 数据集与资源

数据集与资源

  • 数据集名称：IMBench（35 个 robosuite 任务）
  • 数据规模：约 14K 条过滤轨迹，每个任务约 200 条人工演示轨迹用于策略训练
  • 机器人平台：Franka 机器人，配备平行夹爪和吸盘两种末端执行器
  • 观测模态：2-4 个 RGB 视图、本体感知、夹爪状态、腕部力/扭矩传感器
  • 动作空间：统一的 6-DoF 末端执行器增量和夹爪命令，支持单臂和双臂配置
  • 评估模型：

- VLM：GPT-5.5, GPT-5.4-mini, Gemma-4, Claude Haiku-4.5, Claude Sonnet-4.6

- 策略模型：Diffusion Policy, π₀.₅, GR00T N1.5

Card 06 评估与结果

评估与结果

  • 评估环境：robosuite 仿真器，20 个随机种子，每个种子 5 次回滚
  • 主要指标：任务成功率（稀疏奖励：成功=1，否则=0）
  • 关键实验结果：

- Stage 1（约束理解）：Claude Sonnet 4.6 和 GPT-5.5 分别达到 74.5% 和 74.1% 的平均准确率，但在稳定性与平衡任务（P7）上表现最弱（37%-80%）

- Stage 2（计划生成）：GPT-5.5 平均计划正确率约 69.5%，从理解到计划的下降主要在需要时序排序的任务（如 slide-catch），静态几何任务几乎完美传递

- Stage 3（闭环执行）：IMBAgent（GPT-5.5）平均成功率仅 11.3%，即使使用特权物体位姿信息（IMBAgent-obj）也仅 18.8%；需要精确对齐、时序控制、工具使用、隐藏状态推理或平衡的任务全部失败（0%）

- 端到端策略：零样本 VLA 性能极低（≤0.02）；Diffusion Policy 全量训练后达到最佳平均 24%，π₀.₅ 微调后平均 15%，GR00T N1.5 微调后仅 2%

- 分布外泛化：改变任务关键物理因素导致性能显著下降，如 balance-medium 从 0.71 降至 0.12，表明策略依赖记忆模式而非稳健的物理理解

  • 核心发现：VLM 能识别物理约束但难以转化为可执行计划；现有 VLA 模型在零样本下几乎失效，微调后仍表现不佳；直觉性操控是当前基础模型缺失的能力轴
