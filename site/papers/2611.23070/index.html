02论文概述

  • 提出 PAIR（Physical-API Integration Environment for Robots），一个面向智能家居的仿真环境，首次将物理设备操作与基于 Matter 协议 的 API 控制整合到同一共享设备状态中
  • 解决现有具身 AI 仿真环境将家电仅建模为物理对象、忽略智能家居 API 控制的问题
  • 基于对 129 名参与者的调查（保留 1,443 条请求），构建包含 40 个任务和 340 条人类演示的基准，用于评估 VLA 策略在物理与 API 双通道下的表现

03核心贡献

  • 提出 PAIR 仿真环境，基于 OmniGibson 物理仿真，集成 SimuHome 的 Matter 设备模型，实现 API 调用与物理操作的双向状态耦合
  • 构建 84 个智能设备资产，涵盖 14 个家电类别和 4 个传感器类别，每个设备均有功能物理面板和 Matter API
  • 从用户调查中构建 40 任务基准，要求同时包含物理必要步骤和物理可解性，并提供 120 个训练与 120 个评估 episodes
  • 系统评估两种微调 VLA 策略（π0.5 和 GR00T N1.7），揭示物理执行和高层规划的双重瓶颈，并分析规划器通道选择行为

04方法描述

  • 基于 OmniGibson 进行物理仿真，使用 SimuHome 的 Matter 设备模型定义设备状态、命令和操作约束
  • 通过共享设备状态实现 API-物理耦合：API 命令更新状态并反映到面板显示，物理操作更新状态并暴露给 API
  • 每个设备资产提供 三种控制面板变体（P1–P3），物理接口包括按钮、旋钮、触摸屏等，设计参考真实商用家电
  • 高层规划器（默认 Qwen3-VL-8B-Instruct）每 5 秒查询一次，选择物理子任务、继续、等待、结束或 API 调用；VLA 策略执行物理子任务
  • 演示收集使用 XLeRobot 低成本双移动臂，远程操作记录，包含任务级和原子技能演示

05数据集与资源

  • 数据集：PAIR 基准，包含 40 个任务，每个任务 6 个 episodes（3 训练 + 3 评估）
  • 演示：340 条人类演示（120 任务级 + 220 原子技能），总计 5.7 小时，平均每任务演示 130.5 秒、9.9 个子任务
  • 设备资产：84 个智能设备资产，覆盖 18 个设备类别（14 家电 + 4 传感器）
  • 模型：VLA 策略为 π0.5 和 GR00T N1.7（在 340 条演示上微调）；高层规划器包括 Qwen3-VL-4B/8B、InternVL3.5-4B、GPT-6 Luna、Gemini 3.5 Flash-Lite
  • 训练资源：论文未明确说明 GPU/TPU 等训练硬件细节

06评估与结果

  • 评估环境：PAIR 仿真器，120 个评估 episodes（每任务 3 个），端到端运行，动作预算为演示长度的 1.2 倍
  • 主要指标：Task SR（任务成功率）、Subtask SR（子任务成功率）、Progress（首次未完成子任务前的计划完成百分比）
  • 所有 6 种 VLA 变体（两种 VLA 各自独立、+HL、+HL (API)）的任务成功率均为 0.0%
  • 添加 API 访问使设备操作子任务成功率大幅提升（如 π0.5 从 0.4% 到 14.1%），但总任务成功率仍为 0
  • Oracle 评估暴露瓶颈：即使有 oracle 计划和 API 访问，超过 90% 的失败 rollout 停滞在导航、抓取或门操作；物理执行是主要瓶颈
  • 在 oracle 物理执行下，最佳规划器 GPT-6 Luna 的 Progress 仅为 57.3%（oracle 为 100%），显示高层规划也是限制因素
  • 通道选择实验表明规划器更受 面板可见性 影响而非 API 延迟，且 API 使用率与所需面板输入数不成正比
