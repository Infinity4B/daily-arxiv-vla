Card 03 论文概述

论文概述

  • 提出 LoopQ，一个针对视觉-语言-动作（VLA）模型量化方法的闭环、公平评估基准，在同一 checkpoint、相同量化层和相同推理引擎上，仅改变量化方法和 kernel，比较多种量化策略
  • 论文旨在回答三个现有 VLA 量化工作 rarely 回答的基本问题：（1）增益是否来自公平的基线比较？（2）任务成功率是否真的保持？（3）部署后的策略是否真的更快？
  • 评估了超过 180,000 个 episode，并对四个公开的 VLA 量化代码发布进行了可复现性审计
Card 04 核心贡献

核心贡献

  • LoopQ 基准：首个将 VLA 专用方法与通用方法放在同一 scope 下、在三块 GPU 上对真实低比特模型按 kernel 路径计时、并使用配对分布偏移测试鲁棒性的 VLA 量化基准
  • 更少比特 ≠ 更快：真实低比特模型内存节省 2–3 倍，但可能显著比 16-bit 配置更慢（库 kernel 上慢 1.06–1.58 倍），并用 profiling 解释原因（π₀.₅ 的 backbone 是 compute-bound，而 memory-bound 的 action expert 占 63% GPU 时间却保持 16-bit）
  • LIBERO 隐藏了损失：在 LIBERO 上看似无损的配置，在配对的 LIBERO-plus 扰动下损失高达 4.3 个百分点；主要损失来自 VLA 专用方法 ActQuant 和 QuantVLA 以及 4-bit UniVLA
  • GPU 决定速度，方法决定成功率：同样的 4-bit 文件在 L4（int8 kernel）上最多快 14%，在 Jetson AGX Thor 上最多慢 1.9 倍；而任务成功率在三个 GPU 上 90–99% 的 episode 上一致
  • 发布可复现性审计：四个 VLA 量化发布中只有 ActQuant 可以实际计时（且比其自身 16-bit 模型更慢）；QVLA 相对 AWQ 的报告优势在标准协议下消失
Card 05 方法描述

方法描述

  • 受控比较协议：所有比较中仅改变量化器，checkpoint、量化层和引擎保持不变；分别报告 kernel 路径和真实/模拟执行
  • 评估 RTN、AWQ、GPTQ、ActQuant、QuantVLA 五种量化方法，每个模型使用相同的量化层（取自 VLA 专用方法）和相同的校准数据
  • 三层效率测量：隔离测量（空闲 GPU、10 次预热 + 50 次测量）、闭环测量（约 65,000 次调用的中位延迟）、算子级 profiling（Nsight Systems + Roofline 分析）
  • 配对鲁棒性测试：量化策略与其 baseline 在完全相同的 LIBERO-plus 扰动任务上运行，使用配对统计检验（p<0.05，Holm 校正），避免将基线自身失败归咎于量化
  • 关键技术洞察：用 Roofline 分析区分 memory-bound 与 compute-bound 层（H100 的 ridge 约 214 FLOP/B），解释为什么 weight-only 量化对 VLA 无加速
Card 06 数据集与资源

数据集与资源

  • 模型（4 个 VLA）：π₀.₅（3.36B 参数，真实低比特）、GR00T N1.5（模拟量化）、UniVLA（7B，模拟量化）、OpenVLA-OFT（真实低比特 + 模拟量化）
  • 数据集：LIBERO（四个套件，每配置 1,000–2,000 episodes）、LIBERO-plus（七轴扰动：相机视角、机器人初始状态、语言、光照、背景、传感器噪声、物体布局）
  • 硬件：主实验在 NVIDIA H100 NVL 上；补充实验在 NVIDIA L4 和 Jetson AGX Thor 上
  • 规模：H100 上 170,524 个闭环 episode + L4 和 Thor 上 11,310 个 episode，共超 180,000 episodes
  • 量化实现：基于 llama.cpp 的 CUDA 运行时（int8 MMQ、cuBLAS、fused W4A16 kernels）、ActQuant 引擎、官方 OpenPI server；AWQ 使用官方 llm-awq，GPTQ 为自实现（与参考代码 99.7–99.997% 一致）
Card 07 评估与结果

评估与结果

  • 准确率：在 LIBERO 上，8-bit 和 4-bit 的所有方法（通用或 VLA 专用、校准或未校准）均匹配全精度（如 π₀.₅ 上 RTN/AWQ/GPTQ 达 96.7–97.6%）；纯 RTN 在所有四个模型上匹配甚至超过 AWQ 和 GPTQ，校准无可测量收益
  • 鲁棒性：LIBERO 上看似无损的配置在 LIBERO-plus 扰动下损失 1.5–4.3 点；损失主要来自 VLA 专用方法（ActQuant、QuantVLA）和 4-bit UniVLA；QuantVLA 在 GR00T 上损失 4.2 点（Goal 套件单独损失 12.3 点）
  • 速度：H100 batch 1 下，没有量化的 π₀.₅ 或 OpenVLA-OFT 配置比其 16-bit 模型更快（库 kernel 上慢 1.06–1.58 倍）；只有 L4 的 int8 kernel 获益（4–14%），Thor 上所有 4-bit 配置都更慢；仅引擎选择就改变延迟 2.1 倍
  • 内存：真实低比特量化可靠节省内存 2–3 倍（π₀.₅ 4-bit 文件缩小至 2.8 倍，峰值内存节省至 2.3 倍），但收益低于 4 倍（action expert、投影器、KV cache 仍为 16-bit）
  • Profiling 解释：π₀.₅ 量化后的 backbone 是 compute-bound，而其 memory-bound 的 action expert（占 63% GPU 时间、仅 13% 参数）保持 16-bit；即量化的层完全不耗时，调用也最多快 1.09 倍
  • 可复现性审计：四个公开 VLA 量化发布中仅 ActQuant 可计时（且比其自身 16-bit 模型慢 1.25–1.37 倍）；QVLA 报告的相对 AWQ 优势在标准协议下消失；离线动作误差无法预测闭环任务成功率
