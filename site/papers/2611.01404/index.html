Serving Agentic Robot Fleets: Workload Characterization, KV-Cache Thrashing, and Admission Control

01研究单位

02论文概述

  • 论文研究具身智能机器人车队的服务问题，机器人由视觉语言大脑（brain）、工具使用框架和视觉语言动作（VLA）策略组成。
  • 核心挑战是：大脑服务需要维护长期、不断增长的键值（KV）缓存状态，而 VLA 服务必须在严格的控制截止时间内执行动作块；两者共同限制共享 GPU 集群可服务的机器人数量。
  • 通过收集 80 个 LIBERO-PRO 任务轨迹、在 H800 GPU 上分别剖析 brain 和 VLA 两层、并在 vLLM 上重放持续负载，揭示了脑侧 KV 缓存抖动如何降低有效吞吐量，并证明准入控制可恢复性能。

03核心贡献

  • 提出了对具身代理的逐轮上下文增长、工具时序和脑延迟的详细特征化（turn-resolved characterization）。
  • 建立了实验支撑的两层车队容量包络：同时考虑动作截止时间和脑 KV 驻留的联合约束。
  • 在持续车队负载下分析 KV 缓存抖动现象，证明高并发导致重复预填充取代有效生成，从而降低完成的请求和程序数量。
  • 验证了工作集准入控制（静态活跃 episode 上限）能恢复脑吞吐量至缓存驻留状态，并显著提高完整机器人程序的完成速率。

04方法描述

  • 收集 80 个 LIBERO-PRO 任务轨迹，由 GPT-6-Astra（脑）、RPent 工具框架和 π0.5（VLA）产生，包含 1,862 次脑调用和 1,582 个 VLA 推理块。
  • 在 H800 GPU 上分别测量 VLA 的批量推理延迟和脑模型（使用 Qwen3.6-27B 代理，TP=4，vLLM 0.17.1）的 KV 缓存命中/未命中成本。
  • 通过 vLLM 服务引擎重放真实轨迹的请求序列，其中每个虚拟机器人根据记录的上下文增长、token 长度和环境步进间隔发出依赖请求。
  • 采用持续重放（每个机器人完成后立即开始新 episode）和有限重放（每个机器人运行固定数量的 episode）对比，以暴露长期工作集占用效应。
  • 应用静态活跃 episode 上限（K）作为准入控制，并评估一个独立实现的 AIMD 启发式控制器。

05数据集与资源

  • 数据集：LIBERO-PRO 四个套件（object_swap, spatial_swap, goal_swap, 10_swap long），共 80 个 episode，74 个成功。
  • 模型：GPT-6-Astra（脑，低推理 effort）、π0.5（VLA，5 步去噪，5 步动作块）、Qwen3.6-27B（脑服务代理，BF16，TP=4）。
  • 训练/推理硬件：8× H800 80GB GPU，其中脑实验使用 GPU 4-7（4 卡张量并行），VLA 使用 1-2 卡测试。
  • 服务引擎：vLLM 0.17.1，启用自动前缀缓存，混合块大小 784 token，观察到的缓存池为 4,270 和 4,396 块。

06评估与结果

  • 评估环境：H800 GPU，vLLM 服务引擎，脑模型 Qwen3.6-27B，硬件拓扑为 NVLink 互联。
  • 主要评估指标：完整前缀缓存命中率、完成请求吞吐量（requests/s）、完成轨迹程序吞吐量（episodes/min）、控制 tick 饥饿比例（VLA 侧）、Jain 公平指数。
  • 关键结果：

- VLA 容量随控制截止时间急剧变化：0.25 s 截止时间下单 GPU 仅服务 1 个机器人（满足 1% 饥饿 SLO），1.0 s 截止时间下至少服务 32 个。

- 脑侧 KV 驻留影响请求成本：保留 130k token 前缀可将 150-token 调用的时间从约 6.8 s 降至 1.7 s。

- 持续脑负载下，将并发从 20 个机器人增加到 32 个，请求吞吐量从约 2.40 requests/s 降至 0.60 requests/s，同时本地计算的 prompt tokens 上升到约 150 万/分钟。

- 静态活跃 episode 上限（如 K=16）在 N=32 时恢复吞吐量至 2.24–2.25 requests/s，并将完整轨迹程序吞吐量从 1.30 提升至 5.00–5.55 episodes/min。

- 在 N=48 时，K=20 的上限获得最高请求吞吐量 2.377 requests/s，相比无限制的约 0.52 requests/s 提升约 4.6 倍。
