02论文概述

  • 论文提出将机器人与环境建模为 Embodied Turing Machine（具身图灵机），其中机器人与环境状态相当于磁带，策略相当于规则；若状态能被精确表示，决策可完全用代码编写。
  • 基于这一观点提出 Code-Only-as-Policy (COAP)：用代码测量和跟踪机器人、环境与任务状态，仅由代码做出所有决策，测试时无需 VLM 或 VLA 在控制回路中。
  • 论文解决的是现有 VLA 和 Agent Harness 中状态隐式、不可完全检查和控制、改进难以累积的问题，探索一种显式、可控、可积累的机器人策略新范式。

03核心贡献

  • 提出 Code-Only-as-Policy (COAP)：将具身世界视为图灵机，状态存储于代码变量中，相同代码跨 episode 运行，不同任务共享一个代码库，测试时无模型推理。
  • 分析 COAP 相比 VLA 和 Agent Harness 的三大优势：Explicit State（显式状态）、Execution（可控执行）、Extensibility（可扩展性）。
  • 将代码作为 RSI（递归自我改进） 的媒介：编码代理（Claude Opus 5.5 Max）离线开发、调试和合并代码库，每次修改显式、可测试、可回滚，改进稳定累积。
  • 提出 COAP 可作为 高效数据引擎，为 VLA、Agent-as-Policy 和 Harness VLA 稳定生成成功轨迹，作为训练数据。

04方法描述

  • COAP 构建分层共享代码库：任务程序 → 对象操作模块（grasp/pick/place/push/pour）→ 感知与运动控制模块；83% 的代码由新任务复用。
  • 状态分为三部分：环境状态（物体位姿、尺寸、类别、空间关系）、机器人状态（关节角、末端位姿、可达到位姿）、任务状态（阶段、手臂分配、重试计数、需要记忆的信息）。
  • 感知基于 NumPy 和 OpenCV：利用相机模型、机器人网格投影、表平面射线求交，从 RGB 图像中测量物体位姿；测量代码本身可被检查、调试和修正。
  • 代码在运行时冻结，离线由编码代理在闭环中改进：代理在 git worktree 中产生分支，通过 CPU 检查（数值场景、IK 和碰撞验证）、验证集评估和兼容性条件（默认参数不破坏既有任务）后合并。
  • 关键创新点：状态可编程、可回溯到导致失败的变量、测试行为即运行时行为、扩展时通过默认关闭参数保证旧任务行为不变。

05数据集与资源

  • 使用 RoboDojo 基准的 42 个双手机器人任务，涵盖记忆、精度、开放指令、泛化和长时程操作。
  • 输入：一个自然语言指令、三路 RGB 图像（head 和两个 wrist 相机）、关节角、末端执行器位姿、夹爪命令回显。
  • 模型规模：COAP 策略本身无模型参数，运行时仅使用 CPU；开发阶段使用 Claude Opus 5.5 Max 编码代理，非在线推理模型。
  • 训练/开发资源：并行分支以 CPU 模拟验证，不需要 GPU 推理；离线开发循环使用视频记录、状态日志和验证集评估。

06评估与结果

  • 评估环境和基准：RoboDojo 模拟器环境，与当前 VLA / WAM / Agent Harness 方法对比。
  • 主要评估指标：成功率（SR） 和 RoboDojo 进度分数（Score）。
  • 关键实验结果：COAP 在 42 个任务上达到 70.24% 成功率，比最强的 Agent Harness（PhysicalRSI，31.38%）高出 38.9 个百分点，比最强 WAM（Awomo-0.5，29.64%）高出约 40 个百分点。

  • 额外验证：COAP 具备显式状态可实现失败回溯和精确测量；执行上支持失败恢复、毫秒级 CPU 决策；可扩展性上新任务仅需少量代码即可复用、继承或扩展库。
