02论文概述

  • 提出 LOGIV（Long-Horizon Online Graph-based Inference and Verification for Plan Repair），一个面向长时程机器人任务的图工程框架，用显式任务图连接符号规划、基于观测的验证与具身动作执行
  • 解决的核心问题：已完成动作的效果不一定会持续——后续干扰可能使剩余计划所依赖的支撑条件失效（如桥梁装配中支撑被移位），可靠的长时程执行需要同时追踪动作完成状态及其后果的持续有效性
  • 框架运行在现有 VLA 和 WAM 策略之上，无需增加可训练组件，通过依赖追踪确定失败后需恢复的内容，并以保留的未完成动作约束修复目标

03核心贡献

  • 提出图工程（graph engineering）建模形式：在物理任务执行中将“已完成动作”与“其条件支撑的持续有效性”分离
  • 构建闭环实现：结合基于观测的图检查（State Gate / Node Gate / Graph Gate 三道门控）、由保留动作约束的依赖引导局部修复、以及对完整续接计划的符号验证
  • 提出拓扑引导的局部修复方法：通过依赖追踪识别受影响动作，仅修复受影响的支撑操作而保留未受影响的动作，修复失败时扩展替换范围
  • 在两个仿真基准、三个执行骨干和真实机器人上进行了广泛评估，并通过消融实验验证图验证与修复设计的作用

04方法描述

  • 预执行规划：Operator Planner 基于 PDDL Domain/Problem 生成参考计划，经 VAL 验证后编译为任务 DAG，节点为子任务，包含因果边（记录哪个动作供给另一动作所需条件）和资源边（编码资源使用顺序约束）
  • 在线验证：三道门控——State Gate（融合视觉事实与机器人状态）、Node Gate（检查前置条件与动作效果）、Graph Gate（检查资源前驱与条件支撑），使用 GPT-4o 作为 VLM 提取视觉事实，输出 PASS/FAIL/UNRESOLVED 状态
  • 修复范围选择：失败后通过依赖追踪识别受影响动作；已完成的动作保持完成状态，仅当其支撑失效时保留未完成的消费者动作并进行修复
  • 修复规划与验证：从最终目标反向推导修复目标 g_rep，生成修复片段 ΔPt 与保留计划 P_keep 拼接，用 VAL 验证完整计划后再重建任务图并恢复执行
  • 关键创新：将节点的完成状态与其提供支撑的当前有效性分离；修复约束于保留的未完成动作，修复验证失败时扩展替换范围

05数据集与资源

  • 仿真基准：RoboTwin V2（10 个双臂任务）与 BiCoord（10 个双臂任务），每任务 10 个预定义初始状态
  • 执行骨干策略：π₀.₅、AHA-WAM、Light-WAM（均经任务特定微调）
  • VLM 配置：GPT-4o（每次调用最多 512 输出 token）；规划器采用 Fast Downward 的 LAMA-first（30 秒规划时限，5 秒 VAL 验证时限）
  • 真实机器人平台：Astribot S1 全身双臂机器人和两台 AgileX Piper 6 自由度机械臂组成的工作单元，配备第三人称 RGB-D 相机与腕部相机
  • LOGIV 本身不引入任何可训练组件，仅在策略之上增加执行与修复层

06评估与结果

  • 评估指标：无扰动全任务成功率（C）、注入扰动后的全任务成功率（P）、条件恢复率（R）
  • 无扰动仿真结果：三个骨干的平均成功率在 RoboTwin V2 上从 71.67% 提升至 82.33%（+10.67 pp），在 BiCoord 上从 42.33% 提升至 57.67%（+15.33 pp）
  • 扰动设置下：π₀.₅、AHA-WAM、Light-WAM 在 RoboTwin V2 成功率分别达 60%、83%、72%，超越基线骨干 28、23、14 个百分点；在 BiCoord 上为 48%、53%、49%，提升 17、10、10 个百分点
  • 条件恢复率全面超越三个改造的恢复基线（VeriGraph-PDDL、LERa-PDDL、VLM-RP-BT）在所有基准与骨干组合上的表现
  • 真实机器人实验：三个任务（pick_tomato、build_blocks、insert_cable）共 30 次试验，成功次数从 12/30（40.0%）提升至 17/30（56.7%）
  • 消融实验：移除 Graph Gate 使扰动任务成功率从 60% 降至 48%；移除因果依赖追踪使扰动成功率降至 52%；用全量重规划替代局部修复使重复执行的有效动作从 0.2 增至 1.6；移除修复计划验证使条件恢复率从 72% 降至 62%
