02论文概述

  • 提出 SuperGlance，一种将 decoder-only VLM（Qwen3.5-9B）转变为一次前向传播的驾驶策略的方法。
  • 解决现有 VLA（如 Qwen-Drive-1.0）通过逐步解码或扩散生成轨迹导致规划耗时过长的问题（例如 518 ms GPU 时间）。
  • 核心思想是利用 VLM 在生成第一个 token 之前已经将场景编码到隐藏状态，用一个线性头从该隐藏状态直接评分固定候选轨迹，实现“一眼”规划，同时保留 VLM 的视觉问答能力。

03核心贡献

  • 从 decoder-only VLM 的单一隐藏状态读取规划，通过评分固定候选集，使 RL 能够精确最大化所有候选的期望奖励。
  • 多选训练使 VLM 在一次前向传播中保持视觉能力，并迁移到驾驶场景问答。
  • 单个检查点规划仅需 84 ms GPU 时间，比 Qwen-Drive-1.0 快 6.2 倍，在 NAVSIM、WOD-E2E、PAI-AV 和 AlpaSim 上表现至少相当。
  • 在 AlpaSim 闭环中，带延迟下每 at-fault incident 行驶距离是 Qwen-Drive-1.0 的 3.9 倍。

04方法描述

  • 架构：基于 Qwen3.5-9B，输入为当前帧（1024×576）和过去帧（544×320），提示包含 ego 状态、导航命令和指令，末尾为 [ANS] 位置。
  • 候选轨迹：固定 5,273 个候选，包括 4,096 个 NAVSIM 人类轨迹聚类中心、1,024 个 PAI-AV 高速聚类中心、以及 152 个规则生成的候选。
  • 策略头：线性层从 [ANS] 隐藏状态输出候选分布，计划为 top-64 候选的加权平均（温度 0.2）。
  • 训练三阶段：Stage 1 通用 QA（1.16M 问题，双选项顺序对抗位置偏置）；Stage 2 驾驶 QA（124,378 个 DriveLM 问题）；Stage 3 策略训练（监督目标按奖励加权，再进行 KL 正则化 RL，精确期望，无需采样）。
  • 所有阶段使用 rank-32 LoRA，KL 项防止遗忘。

05数据集与资源

  • QA 数据：Stage 1 使用 1.16M 视觉和文本多选问题（来自 VQA、OK-VQA、A-OKVQA、TextVQA 等），Stage 2 使用 DriveLM-nuScenes 的 124,378 个驾驶问题。
  • 驾驶训练数据：NAVSIM 训练集（92,339 场景）、PAI-AV、WOD-E2E 和 rollout 数据（46,583 帧）。
  • 模型：基于 Qwen3.5-9B，LoRA rank 32，隐藏维度 d=4096，候选数 K=5,273。
  • 训练资源：单张 H200 GPU，推理延迟测量基于 batch size 1。

06评估与结果

  • 问答：在 CV-Bench、BLINK、3DSRBench、MMLU、MMLU-Pro、ARC-C、HellaSwag、WinoGrande、BoolQ、TruthfulQA 和 DriveLM 上评估；Stage 3 最终模型在视觉基准上字母准确率与 Qwen3.5-9B 解码相当，DriveLM 高出 24.56 分。
  • 驾驶开放环：NAVSIM PDMS 91.24（RL 后），NC 98.73%，DAC 98.25%，EP 86.18%，TTC 95.56%，Comf 100%。WOD-E2E 和 PAI-AV 上 ADE 优于或接近基线。
  • 驾驶闭环：AlpaSim 中，带延迟（84 ms vs 518 ms）下 SuperGlance 每 at-fault incident 距离 0.970 km（all）和 1.248 km（at-fault），是 Qwen-Drive-1.0 的约 3.9 倍；无延迟时也表现更优。
  • 效率：单次规划 GPU 时间 84 ms，相比 Qwen-Drive-1.0 的 518 ms 快 6.2 倍，且保留 VLM 的问答能力。
