Can LLMs Debug Robots by Editing Their Weights?

02论文概述

  • 论文将“权重空间编程”引入机器人基础策略调试：让 LLM（GPT-6 Astra）直接读取并修改机器人策略的网络权重，无需梯度更新或新演示数据
  • 核心问题是：当机器人已有操作技能但因“词法指令接地失败”而无法执行（如把“activate the cooking appliances heat source”误解为拿盘子），LLM 能否通过权重编辑修复这一连接
  • 论文同时检验编辑器的能力边界：既测试其能否找到有效干预，也测试其能否主动拒绝无法通过自身验证的干预

03核心贡献

  • 对 VLA（π₀.₅）的可复现词法修复：三个独立编辑会话均提升 held-out 改写指令成功率，且结果变化严格局限于含被编辑 token 的指令
  • 系统控制实验：分离编辑方向与编辑规模、完整替换与编辑器插值，并明确词典对照可解释的部分
  • 跨 16 个会话的完整记录（保留与拒绝的编辑），其中 13 个非语言修复会话中 12 个拒绝其候选编辑
  • 单独发现：基准指令元数据使 FastWAM 成功率从 70.0% 降至 48.6%，而被评估 VLA 的总体成功率不受影响

04方法描述

  • 编辑器（GPT-6 Astra）接收策略权重、tokenizer 和持久化 CPU Python 内核（禁止梯度更新、训练循环、目标网络执行），配合预算化的模拟器前向工具进行 practice rollout 与激活探测
  • 成功编辑仅改动 token 嵌入表：对选定源 token 行按公式 E′ᵢ = (1−αᵢ)Eᵢ + αᵢ·Ē(Tᵢ) 向任务锚点嵌入（如 stove、bowl、wine）做插值重映射，强度 0.5–1.0
  • 最佳编辑 C 仅改 65 个嵌入行（132,768 个标量，占导出参数的 0.00367%），不改任何视觉、注意力或动作专家张量
  • 具有结构化局部性保证：指令不含被编辑 token 时，固定输入下动作完全不变；候选值在配对 held-out 评估前冻结，held-out 结果不反馈给编辑器

05数据集与资源

  • 目标模型：openpi 发布的 π₀.₅ pi05_libero 检查点，3.62B 参数（SigLIP 视觉编码 + PaliGemma 风格 VLM 前缀 + flow-matching 动作专家）；另测试 FastWAM 检查点
  • 评估套件：LIBERO 系列（含 LIBERO-Plus、LIBERO-PRO、LIBERO-RECOVER），765 个 held-out 语言改写变体、4,986 个 practice 变体
  • 复现对象：Takehi 等人发布的 Qwen3.5-0.8B p50c 编辑（MATH-500 上得 49.4%，对应原报告 48.1%）
  • 计算资源：CPU Python 工作区（最高 900 秒、96 GB 内存）；每个机器人会话 40–50 次模拟器前向请求，语言修复会话各 50 次；无额外策略训练

06评估与结果

  • 统计方法：同变体、同种子、同初始状态的配对比较，精确双侧 McNemar 检验及 Holm 校正
  • 三个独立会话均改善 held-out 成功率（765 个变体）：A 从 86.3%→89.4%（p=1.82×10⁻⁴）、B 86.3%→88.0%（p=0.0106）、最佳 C 86.3%→92.0%（48 修复/4 回退，p=1.31×10⁻¹⁰）
  • 局部性验证：含编辑 token 的 335 条指令成功率从 74.3%→87.5%（+13.13pp），其余 430 条指令零结果变化；最难改写级别（level 5）从 59.8%→78.2%
  • 控制实验：随机方向、匹配范数的编辑无帮助（p=0.134）；使用编辑器自身词典的全替换解释大部分增益但回退更多，与编辑器直接差异不显著（p=0.0614）
  • 界限证据：另外 13 个机器人会话（FastWAM、相机/背景/语言扰动、恢复、LIBERO-PRO）中 12 个拒绝最终候选；唯一保留的 FastWAM 候选 held-out 增益不显著（p=0.542）
  • 独立发现：LIBERO-Plus 指令元数据使 FastWAM 成功率从 70.0% 降至 48.6%（p=4.36×10⁻¹²），而 π₀.₅ 两种格式下均为 88.6%
  • 结论支持精确词法修复这一狭窄能力，而非一般性缺失技能获取；所有实验均在仿真中完成，未证明物理机器人迁移或语言泛化
