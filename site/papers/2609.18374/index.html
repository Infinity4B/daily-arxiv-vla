Decoupling Vision, Language, and Action for Efficient Multi-Task Robot Policies

02论文概述

  • 研究问题：当前 Vision-Language-Action (VLA) 模型通常依赖数十亿参数的 Vision-Language Model (VLM) 作为骨干网络，在每一步机器人控制中都需要承担高昂的推理延迟和能耗。本文通过受控实验研究：使用解耦的独立视觉编码器、语言编码器和动作头，是否能在多任务操作策略上达到与 VLM 骨干方案 comparable 的成功率，同时大幅提升效率。
  • 核心思路：证明现代 standalone 视觉编码器（如 DINOv3）和 encoder-only 语言模型（如 NeoBERT）已能在嵌入质量上匹配或超越大型 VLM，且通过完全解耦的架构设计可以消除 VLM 骨干在每步推理中的冗余计算。
  • 研究成果：提出的 Decoupled Embodiment Model (DEM) 在 18 个 RoboCasa 模拟任务和 3 个真实机器人任务上，实现了与 VLM 骨干策略相当的成功率，同时推理频率提升 8–17 倍，单次推理能耗降低 6–15 倍。

03核心贡献

  • 在同一实验协议（相同演示数据、任务、训练预算和测量平台）下，系统性地研究了视觉编码器、语言编码器和动作头对解耦策略性能的影响，并与 OpenVLA、Octo、SmolVLA、π₀.₅、GR00T N1.7、TurboVLA、ReactVLA 等 7 个 VLA 基线进行了对比。
  • 提供证据表明，在本文任务范围内，现代解耦组件（DINOv3 视觉编码器 + NeoBERT 语言编码器 + MeanFlow 动作头）在成功率–延迟–能耗权衡上优于 VLM 骨干策略：在 comparable 成功率下，推理频率提升 8–17 倍，单次推理能耗降低 6–15 倍。
  • 开源了 DEM 的代码（https://github.com/Apollo-Lab-Yale/decoupled-embodiment-model），以支持未来高效多任务机器人策略的研究。

04方法描述

  • 整体架构：DEM 采用完全解耦的三模块设计，无共享 VLM 骨干。视觉编码器、语言编码器和动作头独立运行，仅在动作头内部通过 Cross-Attention 进行多模态融合。
  • 视觉编码器：使用 DINOv3 ConvNeXt-B（约 87.6M 参数），从 256 像素输入提取 stage-3 特征图（16×16 网格，512 维），双相机（场景相机 + 腕部相机）共输出 512 个 token。编码器从公开 checkpoint 初始化并微调。
  • 语言编码器：使用 NeoBERT（222M 参数），将指令截断/填充至 32 个 token，保留每 token 的最终层隐藏状态和注意力掩码。编码器保持冻结，且采用缓存机制——指令不变时复用已编码 token，仅在新指令到达时重新编码。
  • 动作头：采用 MeanFlow 模型（107M 参数），单次前向传播即可生成整个动作块（action chunk），替代传统的迭代式 diffusion 或 flow matching 过程。头包含 8 层 AdaLNBlock，通过 Cross-Attention 读取视觉和语言上下文，并使用门控机制（初始化为零）控制每层对上下文的依赖程度。
  • 关键创新：

- 模块完全解耦，可独立替换视觉/语言编码器而无需改动动作头。

- 语言 token 缓存机制，使语言编码成本从"每控制步"降为"每指令"。

- MeanFlow 单步生成动作块，消除了迭代式 head 的多轮前向传播开销。

05数据集与资源

  • 模拟数据集：RoboCasa 厨房场景中的 18 个原子操作任务，涵盖 8 类技能（抓取放置、门、抽屉、旋钮、杠杆、按钮、插入、导航）。使用 NVIDIA PhysicalAI-Robotics-Manipulation-Kitchen-Demos 数据集，每任务 500 个演示 episode。训练时使用 Claude Opus 4.8 生成的 50 个指令同义改写，评估时使用 10 个未见过的同义改写，场景布局随机化。
  • 真实世界数据集：FurnitureBench 的 3 个组装任务（抽屉、台灯、柜子），使用 xArm 7 线性导轨系统（8 自由度），每任务 200 个遥操作演示 episode。
  • 训练资源：8 块 H100 GPU 进行训练（300k 步/模拟任务，100k 步/真实任务）。
  • 评估硬件：单台工作站，配备 RTX PRO 6000 GPU、AMD Ryzen Threadripper PRO 9965WX CPU 和 128GB 内存。延迟测量仅包含策略前向传播（batch size 1），排除相机采集和机器人通信开销；能耗为推理期间平均 GPU 功耗乘以中位延迟。

06评估与结果

  • 评估环境：18 个 RoboCasa 模拟任务（每任务 100 次 rollout）和 3 个真实机器人任务（每任务 50 次 rollout）。
  • 主要指标：任务成功率（Success Rate）、单次推理延迟（Latency, ms）、推理频率（Frequency, Hz）、单次推理 GPU 能耗（Energy, J）。
  • 关键实验结果：

- 模拟任务平均成功率：DEM 达到 55.6%，与 GR00T N1.7（56.9%）和 π₀.₅（54.6%）相当，但参数量仅 417M（每步活跃 195M），远低于 VLM 骨干方案的约 30 亿参数。

- 效率优势：DEM 单次推理仅需 6.1 ms（163 Hz），能耗 2.07 J；GR00T N1.7 为 51.8 ms（19.3 Hz）/ 13.71 J；π₀.₅ 为 103.3 ms（9.7 Hz）/ 31.68 J。即使强制每步运行 NeoBERT，DEM 仍保持 96 Hz / 3.09 J 的最快速度。

- 真实世界验证：DEM 平均成功率 66.0%（抽屉 72%，台灯 82%，柜子 44%），略低于 GR00T N1.7（68.0%），但显著高于 π₀.₅（63.3%）和 TurboVLA（53.3%），且保持 163 Hz / 2.07 J 的低成本。

- 消融实验：

- 视觉编码器微调至关重要（+23 点），冻结 DINOv3 仅 32.6%，微调后达 55.6%；VLM 视觉塔（PaliGemma 2, Qwen3-VL）参数多 5 倍但成功率无提升。

- 语言编码器冻结 NeoBERT 最佳（55.6%），微调无增益；无语言条件时随机成功率仅 11.3%，one-hot 编码 37.4%；VLM 语言模型（Gemma 2, Qwen3-VL）参数多 8–12 倍但成功率无提升。

- MeanFlow 单步生成（55.6%）与 Flow matching（10 步，54.7%）和 Diffusion Policy（16 步，53.8%）成功率相当，但速度快 6–16 倍。

- 动作块长度 H=16（55.6%）和 H=8（55.9%）最优，H=1（每步重规划）降至 50.6%，说明块长度在高速推理下是可选项而非必需。
