Can Astra Solve RoboMME without Breaking the Bank?

01研究单位

  • 作者均来自 Stanford University（斯坦福大学）

02论文概述

  • 提出一种三层系统，用于解决 RoboMME 机器人操作基准测试，处理需要记忆已消失信息的任务（如遮挡前物体位置、演示动作顺序等）
  • 目标是减少对高层大模型（GPT-6 Astra）的调用次数，同时保持接近 oracle 的成功率
  • 系统在 RoboMME 上达到 79.13% 成功率，平均每 episode 仅调用 Astra 3.63 次

03核心贡献

  • 设计了 System 2（GPT-6 Astra 高层规划）+ System 1（π_0.5 VLA 策略）+ System 1.5（微调 Qwen3-VL-4B 监视器） 的三层架构
  • 提出事件触发协调机制：监视器判断子任务完成或特定事件时，才唤醒 Astra 重新规划，大幅降低推理成本
  • 在 RoboMME 上取得 79.13% 总体成功率，比最佳非 oracle 基线（FrameSamp+Modul）高 34.62 个百分点，仅比 GroundSG+Oracle 低 4.95 个百分点
  • 展示了如何通过任务定制历史输入和输出模板，使 Astra 能有效利用视觉历史进行接地规划

04方法描述

  • System 2：GPT-6 Astra 接收任务指令、视觉历史（演示视频或执行帧）、文本进度记录，输出一个可执行的子任务指令（含像素坐标接地）
  • System 1：使用 RoboMME 的 π_0.5 视觉语言动作策略，执行 16 步动作 chunk，保持闭环控制
  • System 1.5：微调 Qwen3-VL-4B-Instruct 监视器，输入 8 帧近期图像、指令开始时图像和当前手腕图像，输出子任务是否完成（或 StopCube 事件）
  • 事件触发：监视器报告完成或任务特定事件（如 StopCube 接近目标、ButtonUnmaskSwap 验证）时，才再次调用 Astra；否则继续使用当前指令

05数据集与资源

  • 使用 RoboMME 基准测试集：16 个任务，每个任务 50 个测试 episode，共 800 个 episode
  • 模型：高层 GPT-6 Astra（medium reasoning effort），低层 π_0.5（RoboMME 发布 checkpoint），监视器 Qwen3-VL-4B-Instruct 微调（LoRA, rank 16）
  • 训练资源：监视器使用 71,835 个示例，LoRA 微调 2 个 epoch，视觉编码器冻结
  • 推理环境：VLA、监视器和模拟器共享一块 NVIDIA L40S GPU

06评估与结果

  • 评估指标：模拟器任务成功率（每 episode 1,300 步预算）
  • 总体成功率 79.13%，其中 Permanence 94.00%，Reference 92.00%，Counting 69.50%，Imitation 61.00%
  • 与基线对比：高于 FrameSamp+Modul（44.51%）34.62 个百分点；低于 GroundSG+Oracle（84.08%）4.95 个百分点
  • 效率：平均每 episode 调用 Astra 3.63 次，平均耗时 80.84 秒；而动作 chunk 平均 24.62 次，调用减少约 85.3%
  • 失败案例：167 个未成功 episode 中，103 个失败、64 个超时；StopCube 和 InsertPeg 各仅成功 9/50 是主要瓶颈
